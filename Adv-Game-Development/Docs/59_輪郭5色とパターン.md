## 1. しくみ（#45 からの変更点）

### 1-A. マスクに「色」ではなく「客の番号」を入れた

#45 はマスクの RGB=色、A=もようだった。欲張り客の2色目と、もようをならべる座標（客の画面での楕円）が4チャンネルに入りきらないので、
A に番号だけを入れて、色・もよう・輪の数・明るさ・楕円は配列（最大64人）で Compose に渡す。
番号をまぜないようにマスクRT は Point フィルタ、シェーダーも点サンプリング。

### 1-B. ダイレートを横→たての2パスにした

もようを見せるには #45 の 3px より太い輪がいる。1パスの (2r+1)² のままだと重くなるので、
「横でいちばん近い点」を先に取ってから、たてで dx²+dy² の最小をとる（正しいユークリッド距離になる）。

| 状況 | さがす半径(mask px) | 1ピクセルあたりのサンプル数 |
|---|---|---|
| #45（3px・1パス） | 3 | 49 |
| #59 輪1本（6px） | 7 | 15＋15 = 30 |
| #59 欲張り客がいるフレーム（6px×2＋すきま2px） | 15 | 31＋31 = 62 |

欲張り客がいないフレームは半径を小さくする（`OutlineFrameData.maxRings`）。サンプル数以外にも配列参照ともようの計算が増えているので、**実際の重さは 3章の再計測で確かめること**。

### 1-C. もようを輪のまわりにならべる座標

ポストエフェクトの輪郭には「線に沿った長さ」がないので、客の Renderer.bounds を画面に写した楕円のまわりの位置を使う。
ただの角度だとたて長の客で横はらの点がつまるので、楕円の弧の長さの近似でならしてある（1:2.5 のたて長で、間隔のむらを 2.5倍 → 1.3倍未満。テストあり）。
くり返し回数は輪のまわりの長さで割り切れる整数にまるめるので、つなぎ目で点が半分に切れない。遠くて小さい客でも最低 `minPatternRepeats` 回はくり返す。

### 1-D. ビルド時の注意（#45 と同じ）

シェーダー3本は `PC_Renderer.asset` の Feature に割り当て済み。Compose のパスが2つになったが、新しいシェーダーファイルは増やしていない。

## 2. 設定値（仮。T1 で調整する）

`Assets/Settings/PC_Renderer.asset` → OutlineRendererFeature → Settings

| 項目 | 既定 | メモ |
|---|---|---|
| bandWidthPx | 6 | 輪1本の太さ（画面px）。1920x1080 基準 |
| ringGapPx | 2 | 欲張り客の2本の輪のすきま |
| dotPeriodPx | 16 | 点線の間隔 |
| dashPeriodPx / dashDuty | 28 / 0.6 | 破線の1つぶんの長さ / 線のわりあい |
| wavePeriodPx | 20 | 波線の1波の長さ |
| minPatternRepeats | 6 | 小さい客でも最低これだけくり返す |
| intensity | 1.4 | #45 のまま。天候・距離では変えない |
| highlightBrightness | 1.6 | 照準が乗った客の明るさの倍率 |

企画書 21章「輪郭パターンの太さと間隔（T1の視認性次第）」。T1 補助試験（8人以上×各パターン5回、正答率95%以上・2秒以内）で未達なら、天候や人数を増やさずにこの表を直す。

- 救済成功（白＋キラキラ）・黒客化（黒）の輪郭は `SetColor` で色だけ変える想定。キラキラの演出は別 Issue
