## 1. 入力イベント

状態機械が受け取る入力はこの 6 つだけ。時刻はすべて秒（`Time.realtimeSinceStartupAsDouble`）。

| 入力 | 発生源 | 備考 |
|---|---|---|
| `PressColor(i)` | 色ボタン i（0〜4）が押された | i は `OmamoriType` の並び＝ボタン箱の左→右 |
| `ReleaseColor(i)` | 色ボタン i が離された | |
| `PressFront` | 正面ボタンが押された | |
| `ReleaseFront` | 正面ボタンが離された | |
| `SwingPeak(strength)` | 振りのピークを検出した瞬間 | strength = ピーク角速度（度/秒）。マウスは 1 |
| `Tick` | 毎フレーム | 長押し 1 秒・チャージ開始など時間で起きる遷移用 |

同一フレーム内の評価順は **ボタン → 振りピーク → Tick**（「色を押して振った」意図を優先）。
逆行した時刻は直前の時刻に丸める。

## 2. 保持する状態

互いに独立した 4 つの状態を持つ（1 本の enum にすると組合せが爆発するため）。

| 状態 | 値 | 初期値 |
|---|---|---|
| 選択色 `SelectedColor` | 0〜4 / 未選択 | `initialSelection`（既定: 健康=0） |
| 正面ボタン `IsFrontHeld` | 押下中 / なし | なし |
| チャージ `IsCharging` | 中 / なし（大祓有効時のみ） | なし |
| クールダウン終了時刻 | 時刻 | −∞ |

デバッグ表示のフェーズは **正面 ＞ チャージ ＞ クールダウン ＞ 待機** の優先で 1 つに畳む。

## 3. 状態遷移表

### 3.1 振りピーク（`SwingPeak`）— 上から順に判定し、最初に当てはまった行で確定

| # | 条件 | 結果 | クールダウン |
|---|---|---|---|
| S1 | セッション外（`GameSession.IsPlaying == false`） | **却下** `Inactive` | 変化なし |
| S2 | 正面ボタン押下中 | **却下** `FrontHeld` | 変化なし |
| S3 | 選択色が未選択 | **却下** `NoSelection` | 変化なし |
| S4 | 現在時刻 ＜ クールダウン終了時刻 | **却下** `Cooldown`（#60: 灰色＋低音） | 変化なし（延長しない） |
| S5 | チャージ中（大祓有効時のみ） | **SwingAccepted（大祓）** → チャージ解除 | 開始 |
| S6 | それ以外 | **SwingAccepted（通常・選択色）** | 開始 |

- 終了時刻ちょうどの振りは受け付ける（`時刻 ≥ 終了時刻`）。
- **色ボタンを押している間に振っても S6（通常投擲）**。長押しは投擲を妨げない。
- 同時刻に 2 回ピークが来ても、2 回目は S4 で却下される。

### 3.2 色ボタン

| # | 入力 | 条件 | 結果 |
|---|---|---|---|
| C1 | `PressColor(i)` | i が押下中でない | 押下順の末尾に i を積み、**選択色 = i**（多重押しは最後に押した色が勝つ） |
| C2 | `PressColor(i)` | チャージ中 | チャージ取り消し → C1 |
| C3 | `PressColor(i)` | 他の色が押下中 or 正面ボタン押下中 | C1。ただし i はチャージ候補にしない |
| C4 | `ReleaseColor(i)` | — | 押下順から外す。**選択色は変えない**（ラッチ） |
| C5 | `ReleaseColor(i)` | i がチャージ中の色 | チャージ取り消し（振らずに離した＝大祓なし） |

- `SelectionChanged` は選択色が実際に変わったときだけ発火する。
- 押しっぱなしの色をもう一度「押す」入力は無視する（レベル値からエッジ化しているので通常起きない）。

### 3.3 正面ボタン（キャリブレーション）

| # | 入力 | 条件 | 結果 |
|---|---|---|---|
| F1 | `PressFront` | — | 押下開始時刻を記録。チャージ中なら取り消し |
| F2 | `Tick` | 押下中 かつ 押下から **1.0 秒以上** かつ 未発火 | **YawCalibrated**（1 回の長押しで 1 回だけ） |
| F3 | `ReleaseFront` | 押下から 1.0 秒以上 かつ 未発火 | F2 と同じ（Tick が粗くても取りこぼさない） |
| F4 | `ReleaseFront` | 1.0 秒未満 | 何もしない（短押しは無効） |

- 正面ボタン押下中の色ボタンは選択を変えるが、長押しの計時は止めない。
- **キャリブレーションはセッション外でも受け付ける**（タイトル・待機・リザルト・プレイ中のどこでも同じ操作）。
- キャリブレーションは「その瞬間の生ヨー角を基準にする」。以後の向きは `ThrowInputController.RelativeYaw`
  （基準からの差、−180〜180 度）を読む。**キャリブレーション直後は必ず 0**。

### 3.4 大祓（長押しチャージ）— 分岐のみ

| # | 入力 | 条件 | 結果 |
|---|---|---|---|
| O1 | `Tick` | 大祓有効 かつ 色を**単独で** 0.8 秒以上押下 | チャージ開始（`ChargeStarted`） |
| O2 | `SwingPeak` | チャージ中 | S5（`ThrowKind.Oharae`）。**現在は発射せずログのみ** |
| O3 | — | 別の色／正面ボタン／振らずに離す | チャージ取り消し（C2 / F1 / C5） |

- `oharaeEnabled` は既定 OFF。OFF の間は O1 が起きないので、長押しはすべて通常投擲。
- 実装は T5 通過後。`ThrowInputController.HandleSwingAccepted` の `Oharae` 分岐に処理を足す。

## 4. SwingAccepted（唯一の発火点）

有効スイングの確定は `InputStateMachine.SwingAccepted` の 1 か所だけで起きる。ここに繋ぐもの：

| 用途 | 結線 |
|---|---|
| 発射 | `TestShooter.inputProviderSource` ← `ThrowInputController`（`FireTriggered` が確定フレームだけ true） |
| 投擲SE | `ThrowInputController.throwSe` を**確定と同じフレームで最初に** `PlayOneShot` |
| お守り選択 | `OmamoriSelector.inputProviderSource` ← `ThrowInputController`（`OmamoriSelectTriggered`） |
| #55 優先救済の対象ID | `ThrowInputController.SwingAccepted`（C# event）で確定時点の対象を弾に保持する |
| #60 着弾目標点の固定 | 同上 |
| #60 クールダウン中の返し | `SwingRejected`（`Reason == Cooldown`）。低音は `cooldownRejectSe` |

`ThrowInputController` は `[DefaultExecutionOrder(-100)]`、`ConecteController` は `-200` で、
受信 → 確定 → 発射が同じフレームに収まる。

## 5. 振りピーク検出（`SwingPeakDetector`）

1. ピッチ角速度 = 角度差（折り返し補正あり）÷ サンプル間隔。振り下ろし（ピッチ減少）を正とする。
2. 角速度 ≥ **180 度/秒**（`triggerVelocity`）で追跡開始。
3. 角速度が前サンプルより下がったサンプルで**ピーク確定**（強さ = 追跡中の最大角速度）。
4. ピーク後は角速度 ≤ **60 度/秒**（`releaseVelocity`）まで再検出しない（1 振り 2 発を防ぐヒステリシス）。
5. サンプル間隔 > 0.1 秒は通信途切れとみなして追跡を捨てる。

- 1 フレームにまとめて届いた行は受信時刻がほぼ同じになるため、検出用の時刻は名目間隔（0.02 秒）で補う。
  `SwingAccepted.Time` には受信時刻を返す（#52 の遅延計測用）。
- 従来の `Shoot2`（5 フレーム前との差 < −15 度で即発射）はピークではなく閾値通過で撃っていた。
  ピーク確定はサンプル 1 個分（約 20ms）遅くなる代わりに、振りの頂点と SE が揃う。
- 閾値は T0-CD（#50）で「両方を満たす値がない」場合に見直す対象。

## 7. 通信形式（ESP32 → Unity）

```
yaw,pitch,roll[,buttons]\n
```

- `buttons` は 10 進のビットマスク。**bit0〜4 = 色ボタン（`OmamoriType` の並び）、bit5 = 正面ボタン**。
  例: 色0＋色3＋正面 = `1 + 8 + 32 = 41`
- 3 項目の行（現行ファームウェア）も受け付ける。その間はボタンを `Esp32RawSource` の代用キー（1〜5 / A）で読む。
- **ファームウェア（`RodController.ino`）は未変更**。ボタンのピン配置が未確定のため、
  上の形式で 4 項目目を送る改修はハード担当と合わせて別途行う。
- `ConecteController` は 1 フレームに 1 行しか読んでおらず、送信周期（20ms）に追いつかず遅延が溜まっていた。
  届いている行をすべて読むように変更した（上限 32 行/フレーム）。

## 8. シーンへの組み込み

1. 対象シーンを開く（例: `Assets/Members/Jungaya/Scenes/TestGame.unity`）
2. メニュー `Toufuku/Input/Setup Throw Input In Active Scene`
   - `ThrowInput` GameObject に `ThrowInputController` ＋ 生入力 ＋ `AudioSource` を付ける
   - `ConecteController` があれば `Esp32RawSource`、無ければ `KeyboardMouseRawSource`
   - `TestShooter` / `OmamoriSelector` / `OnusaAim` の `inputProviderSource` と `PlayerDirect.inputController` を差し替える
3. `ThrowInputController.throwSe` に投擲SE を設定（#64 の素材待ちなら空でよい）
4. Console の警告を確認（`Shoot2` が有効だと独自判定で二重発射になる）
5. 問題なければシーンを保存

## 10. 前提・未決事項

- 仕様書 v8 本文はリポジトリに無いため、Issue #51 / #50 / #55 / #60 / #64 の記述から規則を決めた。
  特に次の 3 点は仕様書と照合してほしい：
  1. 多重押しの優先規則を「最後に押した色が勝つ（離しても選択は保持）」とした
  2. 正面ボタン押下中の振りを「却下」とした（キャリブレーション中の誤射防止）
  3. 「3 箇所すべてこの方式に統一」を、キャリブレーションの入口を正面ボタン 1 秒長押しの 1 本にし、
     シーン状態（タイトル／待機／プレイ中）に関係なく同じ操作で効くようにする、と解釈した
     （従来の `PlayerDirect` の A キー即時リセットは、`ThrowInputController` がシーンにあれば無効）
- `Shoot` / `Shoot2`（独自の振り判定・クールダウン 0.3 秒）は未変更。本番の発射をどちらで行うか決めたら、
  `SwingAccepted` を受けて撃つ形に寄せる。
- 照準の実機化（ヨー／ピッチ → 照準位置）は #60 の範囲。`AimScreenPosition` は当面マウス位置を返す。
