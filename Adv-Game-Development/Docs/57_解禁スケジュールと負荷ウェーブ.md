## 4. 同時上限と負荷ウェーブ（正本：v8 8章「スポーン」「負荷ウェーブ」）

- 基準上限 10人（SPAWN.BASE）。黒客は数えない。総上限 15人を超えない。
- ウェーブ開始から **5秒かけて1人ずつ**上限を上げる（+5 なら1秒に1人、+3 なら約1.67秒に1人）。一斉出現はしない。
- ウェーブ終了時は上限を下げるだけで、超過分の客を帰らせない（自然減）。
- ランク連動の上限（動的難易度）と祭事モードの +5 は、`useTimetable` が ON の間は使わない。

## 5. 負荷の算術（正本：v8 8章「大負荷ウェーブ候補の処理負荷比較」／#53 5.1）

`MockCrowdDirector` の右クリックメニュー「負荷ウェーブの算術を Console に出す (#57)」。Inspector の `Measured Cycle Median` / `Measured Cycle P75` に T0-3M の実測値を入れると判定まで出る。

- 客1人ぶんの平均は、その時刻の比率と客種数値表（付録B B-1）から出す。D満タン秒数は通常客の 15〜25秒を 20秒として加重平均、必要発数は初期R の加重平均。
- ウェーブの中で比率が変わるとき（小負荷ウェーブは 0:48 に遠方客が解禁）は、許容周期がいちばん短くなる時刻の値を使う。
- 判定は #53 5.1 と同じ：**許容周期が p75 より短い案は T3 候補から外す**。小・中の負荷ウェーブは T3 の候補ではないので「追いつかない → 加算人数を見直す」と出す。

## 6. 固定シードとスポーン列（正本：v8 17章／#63）

- 客種は従来どおり「シード × 客種（`PlaytestStreams.Kind`）× 客ID」の乱数で引き、比率だけをその時刻の時間割から取る。乱数の列そのものはプレイヤーの行動に左右されない。
- したがって **同じシード・同じ補充時刻なら同じ客種の列**になる（`SpawnTimetableTests`）。
- 一方、n 番目の客が**いつ**補充されるかは救済・黒客化で空いた時刻で決まるので、プレイヤーの操作が違えば、同じ客IDでも解禁前後にずれて客種が変わる（実例は 9節の run A と B：客21番が 36.88秒なら通常客、38.88秒なら欲張り客）。
- リトライ（`GameSession.Retry`）で時計が 0 に戻ったら、ディレクタの補充待ちチケット・前回の補充時刻・輪郭色の順番・ログ状態を初期化する。これが無いと同じシードでも2回目の列がずれる。

## 10. レビューで見てほしいこと・未決事項

1. **TestGame の数値を本番値に戻した**（8節）。#44 の「残量差が見えるばらつき」「常に黒札3人」は TestGame から消える。視認性の検証は VisibilityMock シーンで続けられる
2. **固定シードの意味**（6節）：同じ入力なら同じ列だが、参加者の操作が違えば n 番目の客の種類は変わる。T3 の固定シード A/B/C で「参加者が違っても同じ客が出る」ことまで求めるなら、客種を客IDではなく時刻の区切りごとの列で引く方式にする必要がある（企画に確認したい）
3. **入場中も D が進む**：客プレハブが `startActive = ON` のため、3秒の入場歩行中から D が進む（6章では定位置到着から）。#62 の未決事項 5 と同じ。算術の前提（D満タン秒数）より実質3秒短い
4. **3:00 以降も D が進む**：新規スポーンは止めたが、`CustomerState` の D 進行と入力の締切（3:00.650 までの解決）は #57 の範囲外で未対応
5. **中負荷ウェーブ（+5・15人・11月）は大+4より重い**（許容 1.29秒）。8章の表は大負荷ウェーブだけを比べているが、移動客30%の11月に総上限15人を入れる中負荷ウェーブが、実は3つの中でいちばん厳しい。T0-3M の実測後に中負荷ウェーブの加算人数も見直し対象にしたい
6. **小負荷ウェーブの許容 1.40秒は想定上限 1.4秒ぎりぎり**。欲張り客30%（R=2）のため
7. **篝火・月名の表示は未実装**。時間割は月（篝火の区切り）を返すだけで、参道の篝火3つと月名1.5秒表示（8章「進行の可視化」）は別 Issue で作る想定
8. **増員の刻み**：「5秒かけて徐々に」を、上限を1人ずつ等間隔で上げる（+3 は 1.67秒ごと、5秒で満員）と解釈した
9. **ご加護タイム（`GokagoTime`）**は TestGame に残っている。完了条件の OFF 対象（祭事演出・動的難易度・ボス・天候）には入っていないが、追加要素なので T3 前に止めるか確認したい
