# 56 笑顔の伝播（有向ペア1回・最大4人・黒客除外・倍率スナップショット）

Issue #56（v8 変更点6／変更点10）。正本は `Docs/投福神社_企画仕様書_v8_完成版.html` の 6章「笑顔の伝播」・7章（縁の計算式／3:00境界）と付録B（B-2／PROPAGATE）。
このドキュメントは**実装がどの規則に従っているか**を1枚にまとめたもので、数値の正本ではない。
数値を変えるときは付録B（Phase 2 以降は移管先スプレッドシート）を直してから、ここと実装を合わせる。

## 1. 何を決めたか

「救われた客が帰り道で別の客に笑顔を伝える」というルールは v8 で入ったが、
**3 秒後に起きる得点へどの倍率を使うか**が決まっておらず、実装ごとに答えが変わる状態だった。
あわせて、対象・回数・上限・終了境界も言葉だけで書かれていた。#56 でこの 5 つを固定する。

| 決めたこと | 値 | どこで判定するか |
|---|---|---|
| 対象 | active かつ 未救済・**非黒客**・R>0 | `CustomerState.IsRescueTarget` |
| 回数 | 有向ペア（救済客→対象客）ごとに 1 回 | `SmilePropagation`（救済客ごとに到達済みIDを持つ） |
| 上限 | 1 回の救済につき 4 人（＝縁は最大 +80） | `SmilePropagation.MaxTargets` |
| 倍率 | **救済完了時**のスナップショット（福の連なり × ご加護） | `SmileMultiplierSnapshot` |
| 境界 | 接触時刻が 180.000 秒**未満**だけ有効 | `SmilePropagation.DeadlineSeconds` |

黒客を対象から外すのは、入れると「**黒客が多いほど縁が増える**」抜け道になるため（v8 変更点10）。
黒客とすれ違っても縁は 0 で、**4 人枠も消費しない**（枠を食えばそれ自体が不利益になり、別の歪みを生む）。

## 2. 伝播 1 件が成立するまで（正本：v8 6章／7章）

```
救済完了（R=0）
  └ ScoreManager.RegisterCorrectHit … 福の連なりを +1 して救済得点を確定
  └ OmamoriHitResolver : SmileCarrier.AttachTo(救済客, スナップショット)
         スナップショット = (＋1 したあとの福の連なり倍率, その弾の発射時のご加護倍率)
退場歩行（3 秒）
  └ SmileCarrier.Update : 毎フレーム、水平距離が接触半径以内の客を探す
       └ SmilePropagation.TryPropagate(対象ID, 対象条件を満たすか, 接触時刻)
            ├ 180 秒以後            → AfterDeadline（何も起きない）
            ├ 自分自身／ID無し／対象外 → NotEligible（枠も減らない）
            ├ 同じ相手に既に伝播済み  → AlreadyPropagated（枠も減らない）
            ├ すでに 4 人           → LimitReached
            └ 成立                 → Applied
       └ Applied のときだけ:
            CustomerState.ReceiveSmilePropagation()   … D を 5 減らす（0 未満にはしない）
            ScoreManager.RegisterSmilePropagation()   … 縁 = round(20 × C倍率 × G倍率)
            PlaytestLog.SmilePropagation()            … 計測ログへ 1 行
```

**対象は予約しない**。救済した瞬間に「この 4 人へ配る」と決めるのではなく、
退場歩行中に実際に交差した時点で、その場で判定する（v8 6章）。
だから移動客が近づいてくれば伝播するし、途中で黒客化した相手には伝播しない。

### 同時刻の解決順

伝播は `Update`（`SmileCarrier`）で起き、黒客化は `LateUpdate`（`CustomerState`）で確定する。
この順のおかげで、v8 6章の「同じイベント時刻では、正色着弾と有効な笑顔伝播を先に解決 → R と D を更新 →
R=0 の救済判定 → なお active で D≥100 なら黒客化」が成り立つ。
**D が 99.9 の客に笑顔が届けば、黒客化はその場で回避される**（#54 の `CustomerStateMachineTests` で固定済み）。

## 3. 倍率スナップショット（正本：v8 7章「倍率の保存順」）

```
伝播得点 = round(20 × 救済時に保存した福の連なり倍率 × 救済時に保存したご加護倍率)
```

| 保存するもの | 確定する瞬間 | 実装 |
|---|---|---|
| 福の連なり倍率 | 救済完了で**+1 したあと** | `ScoreManager.Multiplier`（`RegisterCorrectHit` 実行後に読む） |
| ご加護倍率 | その弾の **SwingAccepted（発射）時** | `OmamoriProjectile.GokagoMultiplier`（#56 で追加） |

- 伝播が起きる時点の倍率へ**差し替えない**。3 秒の間にご加護が切れても、福の連なりが途切れても、保存値のまま計算する。
- 伝播は「連続救済」ではないので、**福の連なり C を伸ばさず、途切れさせもしない**。ご加護専用進捗 G も数えない（v8 10章）。
- 四捨五入は最後に 1 回だけ、0.5 は絶対値の大きい方へ寄せる（`SmilePropagation.Round`）。
  `Mathf.RoundToInt` は偶数丸めなので使っていない（20 × 1.30 × 1.25 = 32.5 → 仕様は 33、偶数丸めなら 32）。
- 大祓（追加T5）で救済した客は両方 ×1.0（`SmileMultiplierSnapshot.Purification`）。大祓本体は未実装なので、
  実装時にこのスナップショットを渡すだけでよい。

## 4. 3:00 境界（正本：v8 7章「3:00境界の処理順」）

- 接触時刻 < 180.000 秒 … 有効。D −5 と縁が入る。
- 接触時刻 ≥ 180.000 秒 … **演出のみ**。D 減少も伝播得点も新しく発生させない。
- 判定は端末のフレームレートではなく**イベント時刻**（`GameSession.ElapsedSeconds`）で行う。
- 境界を過ぎた `SmileCarrier` は自分を `enabled = false` にして、以後の距離計算もやめる。
- `GameSession` を置かないシーン（確認シーン・テスト）では境界なし（`float.PositiveInfinity`）として扱う。

## 5. 数値の出どころ（付録B B-2・PROPAGATE ＝ `ScoreBonusTable`）

| 項目 | 値 | 置き場所 |
|---|---|---|
| 伝播 1 回の縁 | +20 | `ScoreBonusTable.smilePropagationBonus` |
| 1 救済の上限人数 | 4 人 | `ScoreBonusTable.smilePropagationMaxTargets` |
| 1 救済の伝播の縁の上限 | **+80** | `ScoreBonusTable.MaxSmilePropagationBonus`（＝ 20 × 4） |
| 伝播 1 回の D 減少 | −5 ポイント | `CustomerStateMachine.SmileDangerRelief`（#54 から） |
| 境界 | 180 秒 | `GameSession.TotalSeconds`（60秒 × 3ヶ月） |

遠方客の「**基礎200 ＋ 伝播最大 +80**」（v8 7章の選択の比較表）の後半は、この表の 20 × 4 で表している。
T2 で伝播が強すぎ／弱すぎと出たら、**コードではなく `ScoreBonusTable.asset` の数字**を変えて回し直す
（付録B を先に直すこと。付録B に無い値を入れると `OnValidate` が警告する）。

## 8. 積み残し・注意（申し送り）

- **退場歩行が未実装**（`CustomerState.ExitThenDespawn` の TODO）。いまの本番では救済客はその場に 3 秒留まるので、
  伝播するのは**そのとき近くにいた人**だけになる。v8 の「奥から救うほど帰路で多くの人とすれ違う」は、
  歩行が入って初めて効く。`SmileCarrier` は毎フレーム位置を見る作りなので、歩行が入れば**手を入れずに**効き始める。
- **接触半径 2.5m は仮の値**。付録B に接触判定の数値は無い（歩行と当たり判定が決まっていないため）。
  歩行実装時に「すれ違い」の定義（当たり判定の重なり）へ置き換える。`SmileCarrier.DefaultContactRadius` 1 か所。
- **救済得点のご加護倍率は、まだ着弾時の値**を使っている（`ScoreManager.TotalMultiplier`）。
  発射時の保存値（`OmamoriProjectile.GokagoMultiplier`）を使うのは、いまは**伝播だけ**。
  v8 7章は救済得点も発射時の値と書いているので、ご加護タイム（#29）側の Issue で揃えたい。飛翔は最長 0.65 秒なので
  実害が出るのは境界の 1 投だけ。
- **福の連なり倍率が付録B と違う**。実装は `1 + (連なり−1) × 0.1`（上限 3.0）の直線で、
  付録B は 3連続 ×1.10 ／ 6連続 ×1.20 ／ 10連続以上 ×1.30 の段階式。これは #56 以前からの差分で、
  伝播はその値をそのまま受け取るだけ。福の連なり側の Issue で直すときに伝播の値も自動で揃う。
- **神社評価倍率（#30）は伝播に掛けていない**。v8 7章の伝播の式は「20 × 福の連なり × ご加護」だけなので仕様どおり。
  ただし救済得点の側は評価倍率も掛けている（#30 で足したもので、これも付録B の式には無い）。
  どちらへ揃えるかは評価（#30）側の Issue で決める。
- **物理衝突の弾**（`OmamoriBullet` / `TestShooter`）は発射時のご加護倍率を持たないので、着弾時の値で代用する。
  本番の経路は `OnusaThrower` → `OmamoriProjectile` なので実害はない。
- **計測ログの列は増やしていない**。`propagate` 行は既存の列（target_id / gain / en / multiplier / value / detail）に収めた。
  「大祓由来の縁に、その救済客が起こした伝播点を含める」（v8 5章 PURIFY.VALUE）の集計は、
  `detail` の `from:救済客ID` を大祓の救済行と突き合わせれば出せる。
