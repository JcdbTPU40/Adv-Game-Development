# アウトライン描画のノートPC負荷検証 — Issue #45

> 検証の目的は「祭事時に最大15体＋α＝16体同時のアウトライン描画が、
> 展示用ノートPCで 60fps（暫定目標）を満たすか」を実測すること。
>
> **結論: 満たす。** ノートPC実機の**スタンドアロンビルド**で計測し、
> dGPU（RTX 4060 Laptop）で 16体・晴天 437 fps / 1% low 227 fps、
> 意図的に弱い iGPU（Intel UHD Graphics）へ落としても 16体・晴天 97 fps / 1% low 92 fps。
> 詳細は「1. 計測結果」「3. 結論」を参照。

---

## 0. 検証環境

- シーン: `Assets/Members/Jungaya/Scenes/OutlinePerf.unity`
- 生成メニュー: `Toufuku/Perf/Build Outline Perf Scene`
- Unity: 6000.3.13f1 / URP 17.3.0（RenderGraph / Forward+）
- レンダラ: `Assets/Settings/PC_Renderer.asset`
  - Rendering Path: **Forward+**（ステンシル下位ビットが Deferred のマテリアルフラグと衝突するため）
  - Native RenderPass: **OFF**（フルスクリーン Compose の depth-stencil バインドと干渉しうるため）
- 実施日: 2026年09月15日
- 実施者: Jungaya
- 実機: MSI Thin GF63 12VF（ノートPC）
  - dGPU: NVIDIA GeForce RTX 4060 Laptop GPU（既定。Direct3D 12 / VRAM 7956MB）
  - iGPU: Intel UHD Graphics（`-force-device-index 1` で強制。展示機が非力だった場合の下限側として計測）

### 計測条件（重要）

- **Editor ではなくスタンドアロンビルドで計測**。Editor 自身の描画が混ざらないので、絶対値も判断に使える
- **Development Build**。`ProfilerRecorder`（DrawCalls / SetPass / Batches）が非開発ビルドでは無効になるため必須。
  その分のオーバーヘッドが載るので、絶対 fps は**実際より低め＝安全側**に出る
- **Frame Timing Stats: ON**（`PlayerSettings.enableFrameTimingStats`）。
  ビルドで `gpuFrameTime` を取るのに必要。計測用ビルドの時だけ ON にして、後でプロジェクト設定は元に戻してある。
  **再計測するときは ON にし直すこと**（OFF のままだと GPU ms が 0 になる）
- **vSync OFF / targetFrameRate 無制限**（`OutlinePerfHud.uncapFrameRate`、既定 ON）。
  vSync が効くと fps がディスプレイの refresh に張り付き、60fps に対する余裕が読めない
- 解像度: 1920x1080 フルスクリーン
- ビルドするシーンは `OutlinePerf.unity` 1本のみ（Build Settings のシーン一覧は変更していない）

### 操作キー

| キー | 動作 |
|---|---|
| `1` / `2` / `3` | 体数 8 / 12 / 16 |
| `O` | アウトライン ON / OFF（Renderer Feature の有効/無効。ON/OFF 差分が輪郭の純コスト） |
| `F` | 雨天 ON / OFF（`OutlineWeather.RainAmount`） |
| `P` | 計測開始/停止（一定フレーム数を平均） |
| `S` | 体数軸スイープ（12条件×4巡）を開始。**ビルド版でもこれ1つで全条件が取れる** |
| `C` | 計測結果を CSV として `Application.persistentDataPath` に書き出し＋Console に出力 |

### ビルド版のコマンドライン

キー入力なしで丸ごと1回まわす場合:

```
OutlinePerf.exe -outlineSweep=60,4 -outlineQuit -screen-fullscreen 1 -screen-width 1920 -screen-height 1080
```

| 引数 | 意味 |
|---|---|
| `-outlineSweep[=frames,passes]` | 起動後に自動でスイープ開始（既定 60f × 4巡） |
| `-outlineQuit` | スイープ完了後に自動終了。CSV は書き出し済み |
| `-force-device-index <n>` | GPU を選ぶ（Unity 標準）。`1` で iGPU 側に落ちた |

CSV は `Application.persistentDataPath`
（`C:/Users/<user>/AppData/LocalLow/DefaultCompany/Adv-Game-Development`）に出る。起動時に Console へ絶対パスを出している。

### 計測の進め方（推奨）

**判定に使う数値はビルドで取ること。** Editor は自身の描画が混ざって絶対値が当てにならない。

#### A. 再計測する手順（今回やったもの）

1. Player Settings で **Frame Timing Stats を ON**（これを忘れると GPU ms が 0 になる）
2. `OutlinePerf.unity` だけを含む **Development Build** を作る
3. `OutlinePerf.exe -outlineSweep=60,4 -outlineQuit -screen-fullscreen 1 -screen-width 1920 -screen-height 1080` で起動
4. 30秒ほどで自動終了。`persistentDataPath` に `outline_perf_*.csv`（全サンプル）と
   `outline_perf_delta_*.csv`（ON−OFF の Δ と巡間 std）が出る
5. Player.log 末尾の `VERDICT=` 行で体数軸の判定を確認する
6. Frame Timing Stats は元に戻す

弱い GPU 側も見たいときは `-force-device-index 1` を足す。

#### B. 手で1条件ずつ見るとき

1. 体数を `3`（16体）にする
2. `O` で Outline ON、`F` で晴天（Rain OFF）を確認して `P` → 完了ログを控える
3. `F` で雨天 ON にして `P`
4. `O` で Outline OFF にして、晴天 / 雨天それぞれ `P`（ベースライン）
5. 必要なら体数 8 / 12 でも同様に取る
6. 最後に `C` で CSV を書き出す

`S` キーでも A と同じ12条件×4巡のスイープが走る（`OutlinePerfHud.RunAxisSweep(60, 4)` 相当）。

### 暗色検証枠

計測シーンは先頭1体を `#44` 黒客相当 `(0.04, 0.04, 0.06)` の輪郭色にしている（`OutlinePerfDirector.includeDarkTestCustomer`）。
マスク A チャンネルの存在フラグ方式で、暗い色でも他色と同じ太さのリングが出ることを確認する枠。残してある。

### 実機ビルドで新たに判明した不具合（修正済み）

**ビルドではアウトラインが一切描画されていなかった。** 最初のビルド計測で Outline ON/OFF の
DrawCalls 差が 0（Editor では +33）だったことで発覚。

- 原因: `PC_Renderer.asset` の `OutlineRendererFeature.settings` のシェーダー参照3つが未割り当て（`{fileID: 0}`）で、
  `Shader.Find("Toufuku/Outline/...")` へのフォールバックに頼っていた。
  この3本のシェーダーはどのマテリアル/シーンからも参照されていないためビルド時にストリップされ、
  `Shader.Find` が null を返し、`EnsureMaterials` が黙って諦めていた（**ログも出さず**、Editor では再現しない）
- 対処:
  1. `PC_Renderer.asset` の `stencilShader` / `maskShader` / `composeShader` に実体を割り当てた（参照が張られるのでストリップされない）
  2. `OutlineRendererFeature.CreateMaterial` でシェーダーを解決できなかったときに `LogWarning` を出すようにした（次に踏んだら黙って消えない）
- 教訓: **Renderer Feature の見た目は Editor だけでは検証しきれない。** ビルドで1回は目視すること

## 3. 結論（60fps 暫定目標）

- [x] **OK** — 16体・晴天/雨天とも 60fps を満たす
- [ ] 条件付き OK
- [ ] NG

理由・根拠:

```
ノートPC実機（MSI Thin GF63 12VF）のスタンドアロンビルドで計測し、16体同時アウトラインで

  dGPU (RTX 4060 Laptop) : 晴天 437 fps / 1% low 227 fps
                           雨天 458 fps / 1% low 235 fps
  iGPU (Intel UHD)       : 晴天  97 fps / 1% low  92 fps
                           雨天  97 fps / 1% low  90 fps

いずれも avg・1% low とも 60fps を上回る。1% low で見ても最悪フレームは
dGPU 4.4ms / iGPU 10.9ms で、60fps の予算 16.67ms に収まっている。

アウトラインの純コスト（ON−OFF）は 16体・晴天で
  dGPU 0.64ms GPU（16.67ms 予算の約 3.8%）
  iGPU 4.29ms GPU（同 約 26%）
CPU 側は +0.4〜0.5ms 程度。

判定は Development Build（ProfilerRecorder のため必須）で取っており、
その分のオーバーヘッドが載った安全側の値。製品ビルドではこれ以上出る。

したがって「展示機がこのノートPCの dGPU なら大きな余裕あり、
iGPU しか無い機体でも 60fps は満たす」と結論できる。
軽量化（4章）は現時点では不要。ただし本計測シーンは輪郭の負荷だけを切り出したもので、
本編のゲーム負荷は含まない。本編に組み込んだ後、特に iGPU 機では
4章の残り予算（iGPU で輪郭に 26% 使う）を前提に再確認すること。
```

### 体数軸の所見（dGPU / iGPU 両方で一致）

両 GPU とも `VERDICT=FLAT_DOMINATED_BY_DILATE`。

| GPU | 晴天 ΔGPU 8体 | 晴天 ΔGPU 16体 | 体数差 | ノイズ幅 |
|---|---|---|---|---|
| dGPU (RTX 4060 Laptop) | 0.704 ± 0.203 | 0.636 ± 0.101 | −0.069 | ≈0.227 |
| iGPU (Intel UHD) | 4.247 ± 0.027 | 4.289 ± 0.093 | +0.042 | ≈0.097 |

- Δ 自体はノイズより明確に大きい（アウトラインの純コストは有意）
- 一方 **体数差はノイズ幅以下 → 平坦**。DrawCalls の Δ は体数に比例（+17 → +25 → +33）して増えるのに、Δ GPU は動かない
- **Compose のフルスクリーン `(2r+1)²` ダイレートが支配的**で、体数を減らしても軽くならない。
  特に iGPU は巡間 std が 0.03〜0.09ms と極めて小さく、この結論は堅い
- 軽量化が必要になったら、**体数の間引きではなくダイレート側（早期棄却・マスク解像度・半径）**を触ること
- 雨天差: 同体数の晴天/雨天で Δ GPU に有意差なし（Compose の `lerp` 1個程度）。dGPU・iGPU とも同じ

> 2026-08-05 時点の Editor 上のスイープ所見も同じ `FLAT_DOMINATED_BY_DILATE` だったが、
> 当時は Editor 自身の描画が混ざるため絶対値を判断に使えなかった。
> 今回のビルド計測で、絶対値・Δ とも実機の値として確定した。

## 4. 60fps を満たさなかった場合の軽量化選択肢

> **現時点では適用不要**（3章のとおり dGPU / iGPU とも 60fps を満たす）。
> 本編に組み込んだ後に予算が足りなくなった場合に備えて残す。
> 実機の体数軸スイープが両 GPU で「ダイレート支配・体数平坦」と出たので、
> **推奨度は実測で裏が取れた状態**になっている。

効果の目安は相対的。採用時は実機で ON/OFF 差分を取り直すこと。

| 手段 | 期待効果 | トレードオフ | 推奨度（仮） |
|---|---|---|---|
| **ダイレートの早期棄却** | マスク近傍が無いピクセルを即 `discard`（粗いミップやタイル単位判定でさらに削れる）。輪郭は画面のごく一部なので効きが大きい | 実装コスト。端の取りこぼしに注意 | **高（まずここ）** |
| マスクRT解像度を 1/2 | GPU・帯域ダウン大。Compose のダイレートも軽くなる。**ステンシル/色マスク分離後は実際に使える**（`maskResolutionScale=0.5`） | 縁がジャギーになる。細い輪郭で目立つ | 高 |
| マスクRT解像度を 1/4 | さらに軽い（`maskResolutionScale=0.25` も動作確認済み）。ただし `radius = max(1, round(thicknessPx * scale))` の下限により、`thicknessPx=3` では実効太さが画面 4px に張り付く（`thicknessPx < 4` を細く表現できない） | 品質低下が大きい。遠帯では潰れる可能性。細さを保つなら 1/4 は不向き | 中（1/2 で足りないとき） |
| ダイレート半径を下げる | Compose のサンプル数が二乗で減る | 輪郭が細くなり #44 の視認性を損なう | 高 |
| ダイレートを2パス分離（横→縦） | 半径 R で O(R²)→O(R) | 実装コスト・中間RTが1枚増える | 中（半径を保てないとき） |
| 遠帯の客の輪郭を細くする / 間引く | DrawCalls の Δ は減るが、体数軸の Δ GPU は平坦（ダイレート支配）なので GPU 効果は薄い。**実機 dGPU / iGPU の両方で裏付け済み** | 遠方の識別性が落ちる（#44 の論点と衝突） | 低（実測で効果が薄いと確認） |
| SSAO Renderer Feature を切る | ベースライン自体が軽くなる | 画面の立体感が減る。Outline 純コストとは別枠 | 高（余力確保） |
| レンダースケール / 解像度を下げる | 全体の GPU 負荷が下がる | UI・輪郭とも解像感が落ちる | 中 |
| 影の解像度・カスケード段数を下げる | 影パスが軽くなる | 影のにじみ。Outline とは独立 | 中 |

### 推奨の当たり順（仮）

1. **ダイレートの早期棄却** と **マスクRT 1/2**（見た目への影響が限定的で効きやすい。1/2 は実装済みで切替可能）
2. それでも足りなければ **ダイレート半径の見直し** / **SSAO OFF** や影品質ダウンでベースラインを稼ぐ
3. それでもダメなら **2パスダイレート** を検討

遠帯の間引きは最後。実機2機種で「体数を減らしても Δ GPU が動かない」ことを確認済みなので、
視認性（#44）を削る割に GPU が返ってこない。

### ビルド時の注意（#45 で踏んだ）

`OutlineRendererFeature` のシェーダー3本は **Renderer Feature のインスペクタで必ず割り当てておくこと**。
未割り当てだと `Shader.Find` フォールバックになり、ビルドではストリップされてアウトラインが丸ごと消える。
Editor では再現しないので気づけない。解決失敗時は `LogWarning` を出すようにしてあるので、
ビルドで輪郭が出ないときはまず Player.log を見ること。

### 遮蔽の仕組み（要約）

- **Stencil パス:** フル解像度のカメラ depth-stencil に `ZTest LEqual` + `Stencil Replace`（ColorMask 0）
- **Mask パス:** 任意解像度のマスクRTのみ。深度アタッチメント無し。`_CameraDepthTexture` を `SV_POSITION.xy * _OutlineMaskTexelSize.xy` 由来のスクリーンUVでサンプルし、線形深度（メートル）＋バイアスで奥なら `discard`
- **Compose:** `Stencil NotEqual` で内側を除外し、マスクのダイレート外周だけを合成

### パターン拡張点

> **#59 で実装済み。** 5パターン（実線／点線／破線／波線／二重線）、欲張り客の2本の輪、照準で明るくする処理を入れた。
> あわせてマスク A は `(1 + 客の番号) / 255` に変わり、ダイレートは横→たての2パスになった。
> 雨天減衰・距離減衰は企画書 v8 6章（天候中も輪郭の明度を維持）に合わせて削除した。
> 本書の計測値は #45 時点（3px・1パス・パターンなし）のもの。#59 後の値は `Docs/59_輪郭5色とパターン.md` を参照。
