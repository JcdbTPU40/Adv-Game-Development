## 1. 固定シード

### 1.1 何が再現されるか

| 抽選 | 用途（`PlaytestStreams`） | 列の単位 |
|---|---|---|
| 定位置の敷き詰め（MockCrowdDirector） | `SlotLayout` | シードごとに 1 本 |
| 空き定位置の選択・X 座標 | `Placement` | 客ID ごと |
| 黒客にするか | `Identity` | 客ID ごと |
| 初期ゲージ | `Gauge` | 客ID ごと |
| 客タイプ（正解お守り） | `Profile` | 客ID ごと |

- **n 体目の客の抽選結果は、それまでのプレイヤーの行動に左右されない**。UnityEngine.Random（全体で 1 本を共有）ではなく、「シード × 用途 × 客ID」から独立した列を毎回作るため。
- 客ID は計測プレイの開始（リトライ含む）で 1 に戻る。生成に失敗した（空き定位置が無い）ときは ID を消費しないので、次の客が同じ ID・同じ抽選結果を使う。
- 輪郭色は従来どおり 5 色の巡回（乱数を使わない）。

### 1.2 再現されないもの（仕様上の限界）

- **MockCrowdDirector の常時補充はプレイヤーの行動に反応する**。どの定位置が空いているか・今何人黒客がいるかで結果が変わるため、
  「客ID ごとの抽選値」は同じでも、救済の順番が違えば置かれる定位置・黒客の混ざり方は変わりうる。
  操作が同じ（例: 放置）なら完全に同じ列になる（§8.2）。
- 出現の**時刻**はフレーム時間で進むので、数 ms の差は出る。
- 解禁スケジュール・負荷ウェーブの時間割（#57）と移動客の経路（#62）はそれぞれの Issue で本実装する。そのときも `PlaytestRandom.TryFor(用途, 客ID)` を使えば同じ仕組みで再現できる。

### 1.3 シードの決め方

| `seedMode` | 動作 |
|---|---|
| `Fixed`（既定） | 毎プレイ `seed` を使う（リトライしても同じ列） |
| `RandomEachPlay` | プレイごとに新しいシード。使ったシードはファイル名とヘッダーに残るので、あとから `Fixed` で再現できる |

- MockCrowdDirector の定位置は起動時に 1 回だけ敷く。`RandomEachPlay` でリトライしても定位置の配置は最初のシードのまま（客の抽選は新しいシードに従う）。
- 実行中に `L`（配置替え）を押したあとは、従来の `randomSeed` による配置に戻る。

## 2. イベントログ（`…_events.csv`）

### 2.1 保存先とファイル名

| 実行環境 | 保存先 |
|---|---|
| Editor | `<プロジェクト>/PlaytestLogs/`（`.gitignore` 済み。メニュー `Toufuku/Playtest/Open Playtest Logs Folder`） |
| ビルド | `Application.persistentDataPath/PlaytestLogs/` |

```
{テストID}_{yyyyMMdd-HHmmss}_b{ビルド番号}_s{シード}[_{参加者ID}][_incomplete]_events.csv
{テストID}_{yyyyMMdd-HHmmss}_b{ビルド番号}_s{シード}[_{参加者ID}][_incomplete]_summary.csv
例: T3_20260915-143005_b17_s42_P05_events.csv
```

- `GameSession` が時間切れで終わった瞬間に 2 本とも保存する。Play 停止・アプリ終了で途中終了したプレイは `_incomplete` を付けて保存する（`saveIncompletePlays`）。
- UTF-8（BOM 付き）・CRLF。Excel でそのまま開ける。数値の小数点は常にピリオド。未設定の値は空欄、真偽は 1 / 0。

### 2.2 ヘッダー（先頭の `#meta,キー,値` 行）

| `build_number` / `app_version` / `unity_version` / `platform` / `is_editor` | ビルド番号（未設定なら `Application.version`）ほか |
| `seed` / `seed_mode` / `play_index` | 使ったシード・決め方・起動からの何プレイ目か |
| `participant_id` / `operator` / `hypothesis` / `note` | 参加者ID（氏名は書かない）・責任者・検証する仮説・メモ |
| `completed` / `duration_sec` / `session_total_sec` / `event_count` | 完走したか・プレイ秒・1 ゲームの秒・行数 |

| `metrics.*` | 集計の設定（区間の秒・停止の秒・T1 の区間） |

## 3. 集計（`…_summary.csv`）と定義

`section,metric,value` の縦持ち。値が求められないもの（分母 0・到達していない区間）は**空欄＝欠測**（v8 19章: 分母 0 は欠測）。

### 3.1 共通の定義

| 用語 | 定義 |
|---|---|
| 振り | `fire` と `swing_rejected`（`Inactive` を除く） |
| 停止 | 振りと振りの間（開始 → 最初の振り、最後の振り → 終了も含む）が **3 秒以上**（`idleThresholdSeconds`）の区間 |
| 命中率 | 客に当たった着弾 ÷ 着弾（`landing` のみで数える） |
| 正色命中率 | 相性◯で当たった着弾 ÷ 着弾 |
| 黒客化率 | 黒客化数 ÷（救済数 ＋ 黒客化数） |
| 同時黒客 | 黒客として出現 or 黒客化してから退場するまでの客の数。区間の最大には区間開始時点の残りも含める |
| 区間 | `t` が [開始, 終了) に入るイベント。最後の区間は終了後の端数も含む |

### 3.2 `play`（全体）

`duration_sec` / `throws` / `normal_throws` / `oharae_throws` / `rejected_swings` / `landings` / `hits` / `hit_rate` / `good_hits` / `good_hit_rate` /
`color_errors` / `rescues` / `black_conversions` / `black_conversion_rate` / `max_simultaneous_black` / `idle3s_count` / `idle3s_total_sec` /
`en_final` / `max_fuku_chain` / `rating_final` / `rank_final` / `max_rank` / `max_rank_sec` /
`throw_interval_sec.{count,p50,p75,p95,max}`（実操作周期 = 発射の間隔。T0-3M と共用）

### 3.3 `t1`

| 指標 | 定義 | 17章 T1 の合格値との対応 |
|---|---|---|
| `stage{n}.result` / `start_sec` / `end_sec` / `duration_sec` | #58 が記録した段階の開始・終わり（achieved / timeout） | 各段階の未達が 2 人以下 |
| `stages_recorded` / `unachieved_stages` | 記録された段階数・時間切れの段階数 | |
| `free_practice_sec` | 明示値。無ければ最後の段階を達成してから学習区間の終わり（30 秒）まで | |
| `counter_reset_sec` | 0:30.000 のカウンタ初期化を記録した秒 | |
| `first_rescue_sec` | 最初の救済の秒 | 8/10 が 15 秒以内 |
| `first_correct_color_throw` | 初めて正しい色を当てた発射番号 | 9/10 が 2 投目まで |
| `color_errors` / `idle3s_count` / `idle3s_total_sec` | 学習区間（0〜30 秒）の色誤り・停止（区間内に始まった数 / 区間内の秒） | |
| `ghosts` / `interventions` | ゴースト表示・介入（全部）の回数 | |
| `staff_interventions` / `ghost_interventions` | 介入のうち、スタッフ（`detail` が `ghost` で始まらない）／0:30 のあとの状況別ゴースト（`ghost:…`）。#58 で追加 | スタッフ介入 1 人以下は `staff_interventions` |
| `stage1_idle_ghosts` / `after_learning_ghost` | 教える1で3秒止まったときの大幣ゴーストの回数／0:30 のあとに出した状況別ゴーストの種類（`swing` / `aim` / `color` / `priority`、出していなければ空欄）。#58 で追加 | 修正の順（配置・同期パルス・照準反応・ゴースト）の判断材料 |

### 3.4 `t2`

| 指標 | 定義 |
|---|---|
| `trial_start_sec` | `t2_trial_start` の秒（無ければ 0 = セッション開始） |
| `decision_sec` | 試行開始 → 最初の発射確定 |
| `first_target_id` / `first_target_category` / `first_target_color` / `first_target_was_priority` | 試行開始後に最初に当たった客 |
| `choice.total` / `choice.category.<分類>` / `choice.color.<色>` / `choice.priority` / `choice.non_priority` / `choice.priority_share` | 試行開始後に当たった客の分布。優先対象かどうかは発射確定時の優先対象ID と照合 |

「最初に選ばれる対象が 1 種類へ 70% 超で偏ったら支配戦略」（v8 11章）は、複数プレイの `first_target_category` を集計スクリプトで数えて判定する（§6）。

### 3.5 `t3`（0-60 / 60-120 / 120-180 秒）

区間ごと（`0-60s.` など）: `throws` / `landings` / `hit_rate` / `good_hit_rate` / `idle_sec` / `rescues` / `black_conversions` / `black_conversion_rate` / `max_simultaneous_black` / `rating_end` / `rank_end`（区間の終わりの評価）

| 合計・比較 | 定義 | 17章 T3 の合格値との対応 |
|---|---|---|
| `total.idle_sec` | 停止の合計秒 | 総停止時間の中央値 < 18 秒 |
| `last_segment.hit_rate_drop_pt` | （最初の区間の命中率 − 最後の区間の命中率）× 100 | 最終 1 分の命中率低下 ≤ 15pt |
| `last_segment.throws_drop_ratio` | 1 − 最後の区間の投擲数 ÷ 最初の区間の投擲数 | （T0-3M: 初分比 20% 以内） |
| `last_segment.black_conversions_le_rescues` | 最後の区間で 黒客化数 ≤ 救済数 なら 1 | 最終 1 分の黒客化数 ≤ 救済数 |
| `total.max_simultaneous_black` | 同時黒客の最大 | 同時黒客 ≤ 5 人 |

### 3.6 `input`

| 指標 | 定義 |
|---|---|
| `receive_to_fire_ms.{count,p50,p75,p95,max}` | Unity 受信 → 発射確定（Unity 内の処理遅延） |
| `input_to_receive_jitter_ms.{…}` | コントローラ側の入力時刻 → Unity 受信の**揺らぎ**（最小値を 0 とした差）。時計の原点が違うので絶対値は出さない |

## 4. 入力時刻／Unity受信／発射確定（T6-USB #52 と共用）

| 列 | 取り方 |
|---|---|
| `input_time` | ESP32 の受信行の **5 項目目**（`millis()`）。`yaw,pitch,roll,buttons,millis`。振りピークを確定したサンプルの値 |
| `receive_time` | そのサンプルを `ConecteController` が読んだ時刻（`SwingAccepted.Time`） |
| `fire_time` | `ThrowInputController` が `SwingAccepted` を配った時刻 |

- 現行ファームウェア（`RodController.ino`）は 3 項目しか送らないので、`input_time` は空欄になる。5 項目目を送る改修はハード担当（プログラム A）と合わせて行う。4 項目（ボタンのみ）も従来どおり受け付ける。
- 5 項目目が入ったことで、従来「受け付けない行」のテストケースだった `1,2,3,4,5` は有効な行になった（テストは `1,2,3,4,5,6` に変更）。
- 画面に弾が出るまでの遅延（v8: SwingAccepted → 画面 p95 80ms）は描画のフレームを含むので、このログだけでは測れない。T6-USB の外部計測と合わせる。

## 6. 集計スクリプト（中央値・p75・p95）

```bash
python Tools/playtest_aggregate.py                          # PlaytestLogs/ 以下をすべて
python Tools/playtest_aggregate.py PlaytestLogs --test-id T3 --build 17
python Tools/playtest_aggregate.py PlaytestLogs --group-by test_id,build_number,seed
python Tools/playtest_aggregate.py --self-test
```

- `*_summary.csv` をテストID × ビルド番号ごとにまとめ、指標ごとに `n / median / p75 / p95 / mean / min / max` を `aggregate_YYYYmmdd-HHMMSS.csv` に出す。
- `pooled` 行: 同じ組の `*_events.csv` から 1 投ごとの値（`throw_interval_sec`・`receive_to_fire_ms`）をプレイをまたいで束ねた分布。
- 文字列の指標（`first_target_category` など）は最多の値と占有率を出し、T2 の最初の標的が 70% 超に偏ったら画面に警告する。
- 途中終了（`completed=0`）は既定で除く（`--include-incomplete`）。
- 分位点は線形補間。**Excel なら `PERCENTILE.INC(範囲, 0.75)` / `MEDIAN(範囲)` と同じ値**になるので、表計算で確認するときは `*_summary.csv` を開いて `metric` で絞り込み、`value` 列にこの関数を使う。

## 9. 前提・未決事項
