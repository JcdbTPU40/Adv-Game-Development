## 2. 縁の計算式（正本：v8 7章「縁の計算式（通常弾）」／付録B B-2）

```
救済得点 = round((基礎点 + 最終弾の命中精度加点 + 優先救済加点) × 救済時の福の連なり倍率 × 発射時のご加護倍率)
伝播得点 = round(20 × 救済時に保存した福の連なり倍率 × 救済時に保存したご加護倍率)
```

- **四捨五入**：`Mathf.RoundToInt` は 0.5 を偶数へ丸める（162.5 → 162）ので使わない。`EnFormula.RoundHalfUp` で 0.5 を切り上げる（162.5 → 163、32.5 → 33）。
- **float の端数**：倍率は `decimal` に直してから掛ける（float → decimal は有効数字7けたで丸まるので 1.1f が 1.1 になる）。
- **欲張り客**：1発目は縁 0・C も増やさない（5秒タイマーだけ戻す）。R=0 の弾で基礎点 300 を一括し、その弾の精度・優先救済・倍率を1回だけかける。
- **倍率の保存順**：救済完了で C を +1 → その段の倍率を確定 → 救済得点を足す → `(C倍率, ご加護倍率)` を保存。保存値は `ScoreManager.LastRescueSnapshot` と `OmamoriHitInfo.RescueSnapshot` に出る。
- **ご加護倍率**：`OmamoriProjectile.Launch`（SwingAccepted と同じ呼び出し）で `ScoreManager.GokagoMultiplier` を保存する。飛翔中にご加護が始まっても終わっても変えない。
- **ランクと危険度 D は倍率に入れない**（付録B「ランク すべて×1.0」、7章「危険度は倍率にも閾値にもしない」）。

### 伝播得点について（#56 との分担）

伝播の**点数計算と入口**（`ScoreManager.RegisterPropagation(EnMultiplierSnapshot)`）までが #61。
「どの客に・何人まで・同じ有向ペア1回」を決める判定は #56 の担当で、判定したら `OmamoriHitInfo.RescueSnapshot` を渡して呼ぶ。
3:00 以後（`GameSession.IsPlaying == false`）の呼び出しは 0 点を返す（7章「伝播は接触時刻が180.000秒未満のものだけ有効」）。

## 5. 3:00 境界（正本：v8 7章「3:00境界の処理順」／付録B GAME.END）

```
プレイ中 IsPlaying
  │ 経過 ≥ 180.000秒
  ▼
解決中 IsResolving（onTimeUp）
  ・入力受付・スポーン・危険度の進行を止める（ThrowInputController / Spawner / CustomerState が IsPlaying を見る）
  ・3:00 前に受理した弾（OmamoriProjectile.PendingSessionShots）の着弾は得点に入る
  ・新しいご加護タイム・伝播得点は作らない
  │ 受理済みの弾が 0 になった（おそくとも 180.650秒）
  ▼
終了 IsFinished（onSessionEnd）
  ・ScoreManager.LockScore() / ShrineRating.Lock() → 以後は縁・C・評価が動かない
  ・DailyBestRecorder がベストを登録 → ResultScreen を出す
```

- どの弾も「発射時刻 + 飛翔時間（≤0.65秒）」で落ちるので、「締切の時刻になったら固定」ではなく「受理済みの弾が 0 になったら固定」にしている。
  同じフレームの中で GameSession が弾より先に動いても、落ちる前の弾の得点を切り捨てない。
- 弾が落ちる前に壊された場合は `OnDestroy` で数から外す。それでも残ったときの保険として、180.650秒 + `resolveGraceSeconds`（0.5秒）で強制的に固定する。
- 時計はまだフレームの `deltaTime` の合計。単調増加時計・自動復帰・障害処理と、19章の「3:00境界ログ」は #65 の担当。

### 「画面外から読める」の基準

展示モニターは会場備品でサイズ未定（16章）なので、文字の大きさは画面の高さのわりあいで持ち、`HudLegibility` で読める距離を計算する。

- 読める目安：文字の高さが見る人から **22分角**以上（ANSI/HFES 100 の推奨 20〜22分角）。文字の高さ 1cm ≒ 1.56m。
- 数字・英大文字の高さはフォントサイズの 72%（Noto Sans JP の cap height ≒ 0.733em）。
- 列の後ろの距離：プレイヤー約 2.5m ＋ 観客境界 2m（13章）＋ 列 ≒ **画面から 7m**。

| モニター | 縁（0.15） | 今のランク（0.18） | 今日のベスト（0.105） |
|---|---|---|---|
| 40インチ | 8.4m | 10.1m | **5.9m**（7m に届かない） |
| 50インチ（テストの基準） | 10.5m | 12.6m | 7.4m |
| 65インチ | 13.7m | 16.4m | 9.6m |

EditMode テスト `HudLegibilityTests` が「50インチ・7m」で3つとも読めることを確かめる。40インチ以下のモニターになったら `bestFontRatio` を上げる（7m に必要なわりあいは `HudLegibility.RequiredFontSizeRatio(7, インチ)`）。
