## 2. 時計（正本：v8 7章「Unityの単調増加時計で…端末のフレームレートではなくイベント時刻で判定する」）

```
Time.realtimeSinceStartupAsDouble（単調増加）
  │ 前のフレームとの差だけ足す（timeScale・deltaTime は使わない）
  │ ・止める理由が1つでもあれば足さない（Paused / LinkRecovery）
  │ ・1回で 0.5秒をこえたぶんは足さない（StalledSeconds に記録）
  ▼
SessionClock.Elapsed ＝ GameSession.ElapsedTime（秒）
```

- **止める理由**はビットで持ち、ぜんぶ外れた時刻から続きを進める。止めた瞬間までの時間は足してから止める。
- **引っかかりの上限 0.5秒**：ロード・COM ポートを開くときなどに 1 フレームが数秒になると、D が一気に進んで黒客になる。0.5秒をこえたぶんは「止まっていた」とみなす。2fps を下回るとゲームの時間が現実よりおそくなる。
- **イベント時刻 → 時計の秒**（`SessionClock.ElapsedAt`）：最後に進めた時刻よりあとなら足し、前ならさかのぼる。ただし再開・引っかかりより前にはさかのぼらない。
- **実行順**：`GameSession`（-300）→ `ControllerLinkSupervisor`（-250）→ `ConecteController`（-200）→ `ThrowInputController`（-100）→ その他。フレームの始めに時計を進めてから、そのフレームで受け取った入力を判定する。
- **ポーズ中の世界**：`freezeWorldWhileHeld`（既定 ON）で `Time.timeScale = 0`。客の歩行・弾の飛翔も止まる。解除やシーン移動でもとの値にもどす。

### 時計で進めるもの

| 使う値 | 足す区間 | 使っているところ |
|---|---|---|
| `ElapsedTime` | ぜんぶ | 3:00 の判定、月、時間割（#57）、福の連なりの 5秒（`ScoreManager` の既定の時計）、計測ログの時刻 |
| `PlayDeltaSeconds` | [0, 3:00.000) | 危険度 D（`CustomerState`）、スポーンの間かく（`RescueCustomerSpawner`）、ご加護の残り時間（`GokagoTime`） |
| `CompetitionDeltaSeconds` | [0:30.000, 3:00.000) | ランクC停滞タイマー（`ShrineRating`） |

`PlayDelta` / `CompetitionDelta` は「前のフレームの時計の秒 → 今の秒」と区間の重なり（`SessionBoundary.Overlap`）なので、フレームの区切り方がどうでも合計が同じになる。3:00 をまたいだおそいフレームでも、3:00 のあとのぶんは D に足さない。

## 4. ボタン箱の 100ms（正本：v8 3章「Unityは100ms受信がなければ全ボタン解放として入力・チャージをキャンセルする」）

- `Esp32RawSource` がボタン付きの行を受け取るたびに `ButtonLinkWatchdog.Receive(受信時刻, 押下マスク)`。
- 最後の受信から **100ms 以上**たったら `IsColorHeld` / `IsFrontHeld` がぜんぶ false。一度も受け取っていない間は見張らない（ボタンを送らないファームウェアと代用キーのため）。
- `ThrowInputController` は、はなした時刻を **とぎれた時刻（最後の受信 + 100ms）** にする。フレームがおそくても、ため（大祓）や正面ボタン 1秒長押しがとぎれたあとに成立しない。
- とぎれた瞬間に `[ThrowInput] ボタン箱の受信がとぎれた → 全ボタン解放`、計測ログに `button_link_lost`、`ThrowInputController.ButtonLinkLost` イベント。選んでいる色はそのまま（#51 の規則）。
- 30Hz のハートビート（33ms 間かく）なら 2 回まで落ちてもとぎれない。

## 5. 通信の切断と USB へのフォールバック（正本：v8 3章「接続」、13章「無線切断→有線に差し替え」）

```
受信の間かく ≥ 0.5秒（ControllerLinkWatch）
  ├ プレイ中・解決中なら GameSession.Hold(LinkRecovery)：時計・D・スポーン・5秒・C停滞が止まる、振りを受け付けない、timeScale 0
  ├ SessionHoldOverlay「コントローラーの通信が切れました／USB ケーブルを挿しなおしてください」
  └ 2秒ごとに ConecteController.BeginReconnect()：今のポートを閉じ、別スレッドで COM ポートを順に開いて ESP32 の行を待つ
        前につながっていたポートは最後に試す → 無線の仮想 COM ポートが止まっていても、あとから挿した USB を先に見つける
受信が 0.3秒続く
  └ Release(LinkRecovery)。[Link] 復帰（とぎれていた秒）、計測ログ link_recovered（値＝とぎれていた秒 ＝ T7 の復帰秒）
```

- ゲームは止まらない（探しなおしは別スレッド）。ケーブルを抜いて読めなくなったら `ConecteController` がポートを閉じて `isConnected = false` にする（前は例外をにぎりつぶしてフラグを戻さなかった）。
- タイトルやリザルトでとぎれても時計は止めない（止めるのはプレイ中・解決中だけ）。とぎれたままリトライで始まったプレイは止める。
- 開発のキーボード操作では一度も受信しないので何もしない。展示で起動時にまだ挿していないなら `scanWhileNeverConnected` を ON。
- `ConecteController` はシーンが変わるとき（`OnDestroy`）もポートを閉じる。閉じないとタイトルからもどったシーンで開けない。

## 6. 自動復帰とフリーズの再起動（正本：v8 11章「自動復帰」、13章 1試遊サイクル・アテンド手順書、17章 T7「故障しても60秒以内に戻せる」）

### 6.1 アプリが動いているとき（`ExhibitAutoReturn`）

| きっかけ | 動き |
|---|---|
| リザルトを出してから 20秒（13章 1試遊サイクルのリザルト 20秒） | タイトルのシーン（既定 `Start`）へ |
| F12 を 1.5秒長押し | プレイ中でもすぐタイトルへ |

タイトルのシーンが Build Settings にないときは警告だけ出して何もしない。

### 6.2 アプリが固まった・落ちたとき（`ExhibitHeartbeat` + `Tools/exhibit_watchdog.ps1`）

```
powershell -ExecutionPolicy Bypass -File Tools\exhibit_watchdog.ps1 -ExePath "D:\Build\Toufuku\Toufuku.exe"
```

- 見張りがゲームを `-toufukuHeartbeat "%TEMP%\toufuku_heartbeat.txt"` 付きで起動する。ゲームはメインスレッドが動いている間、1秒ごとにファイルを書く。
- **10秒**更新がない（フリーズ）・プロセスが終わった（クラッシュ）・起動から **45秒**たっても書かれない、のどれかで強制終了して起動しなおす。
- `exhibit_watchdog_log.csv`（exe と同じフォルダ）に `start` / `failure` / `recovered` を残す。`recovered` の秒は「最後にファイルが書かれた時刻 → 起動しなおしたゲームが書いた時刻」＝**復帰秒**（T7）。
- 起動しなおしたゲームは Build Settings の **0 番のシーン**から始まる。今の 0 番は `Assets/Scenes/SampleScene.unity` なので、展示ビルドでは 0 番をタイトル（`Start`）にする必要がある（9節）。

### 6.3 60秒の見積もり

| 区間 | 秒 |
|---|---|
| 固まってから見張りが気づく | ≤ 10.5（StaleSeconds 10 + 見回り 0.5） |
| 強制終了 | ≤ 5 |
| 起動 → 最初のシーンの読み込み → 生存確認ファイル | 未計測（展示ビルドで測る。ここが 40秒をこえると 60秒に入らない） |

### 6.4 アテンド手順書（13章）に書くこと（案）

1. **「コントローラーの通信が切れました」が出た**：大幣の USB ケーブルを挿しなおす（無線なら有線のケーブルを挿す）。数秒で自動でつながり、ゲームの時間は止まったまま再開する。
2. **画面は動いているのに進まない・入力がおかしい**：キーボードの **F12 を 1.5秒長押し** → タイトルへもどる。
3. **画面が固まった・ゲームが消えた**：何もしない。見張りが 10秒で気づいて起動しなおす（タイトルまで待つ）。見張りのウィンドウも消えていたら、デスクトップの「投福神社（見張り付き）」を起動する。
4. **コントローラーが壊れた（T7 の交換訓練）**：予備の大幣・ボタン箱に差し替える → 通信が復帰したら、画面の的に向けて**正面ボタンを 1秒長押し**。
5. 一時停止が必要なとき（安全確認など）：**F9** で止める／再開。

## 7. ランクC停滞タイマー（正本：v8 11章「競技開始の0:30.000から計時し、B以上へ上がった瞬間に0へ戻す。学習中、ポーズ、リザルト、通信復帰中は加算しない」）

- `ShrineRating.Update` が `GameSession.CompetitionDeltaSeconds` を足す。学習中（0:00〜0:30）・3:00 以後（リザルト）・止めている間（ポーズ・通信の復帰中）はこの値が 0。
- ランクが B 以上に変わった瞬間に 0。C に落ちたら 0 から数えなおす。リトライで 0。評価を固定したら数えない。
- 読める値：`ShrineRating.RankCStallSeconds`、`IsRankCStalled`（30秒以上）。**動的難易度（満タン秒数 ×1.2）は未採用**（MVP 合格後の追加・TA）なので、今は難易度を変えない。

- **展示ビルドでの見張り**: `exhibit_watchdog.ps1` は構文だけ確かめた（PowerShell のパーサーでエラー 0）。ビルドがないので、フリーズ → タイトルの秒は未計測（6.3節）。

## 9. 範囲外・未決事項

- **Build Settings の 0 番**: 今は `Assets/Scenes/SampleScene.unity`。見張りが起動しなおすとここから始まるので、展示ビルドでは 0 番をタイトル（`Start`）にする。シーンの流れは小林さんと相談（Build Settings は変えていない）。
- **ボタン箱の通信形式（プログラムA）**: 仕様は「連番＋6bit 押下マスクを状態変化時と 30Hz ハートビート」で、大幣とは別の ESP32。今のファームウェアはボタンを送らず、Unity は大幣と同じ行の 4 項目目で受け取る形（#51）。連番による欠落の検出はしていない。100ms の見張りは、ボタン付きの行が届く形ならどちらでも同じように効く。
- **BLE**: Unity 側は Bluetooth の仮想 COM ポートとして読む前提（`ConecteController` はシリアルポートを探すだけ）。T6-BLE は別 Issue。
- **`ConecteController`（淡路さんのファイル）を変えた**: 読めなくなったらポートを閉じる、別スレッドの探しなおし、シーンが変わるときに閉じる。起動時の探し方（メインスレッドで順に 2秒ずつ）は前のまま。
- **段階学習（#58）**: まだないので、0:30 での全カウンタの初期化はしていない。`learningSeconds` はランクC停滞タイマーだけが使う。
- **天候の時計**: 天候はまだ晴のみで時計がない。天候を足すときは `GameSession.PlayDeltaSeconds` で進める。
- **笑顔の伝播の判定（#56）**: 接触時刻を渡す入口（`RegisterPropagation(snapshot, 接触の秒)`・`ReceiveSmilePropagation`）までを用意した。
- **`Time.timeScale` を使うほかの演出**: 止めている間は 0 にするので、`CutInController`（スローモーション）とは競合する。今の TestGame には置いていない。UI のアニメは `unscaledDeltaTime` で。
- **動的難易度**: 停滞タイマーは数えるだけ。×1.2 を入れるのは TA の Issue。
- **引っかかりの上限 0.5秒**: 2fps を下回る環境ではゲームの時間が現実よりおそくなる（T6 の 60fps の基準から見て起きない想定）。

## 10. 手動で確認してほしいこと

1. `Assets/Members/Jungaya/Scenes/TestGame.unity` を再生し、プレイ中に **F9** → 「一時停止中」が出て客も弾も止まり、もう一度 **F9** で続きから動く（残り時間が止まっていた秒だけずれる）。
2. **F12 を 1.5秒長押し** → `Start`（タイトル）へもどる。短く押しただけでは何も起きない。
