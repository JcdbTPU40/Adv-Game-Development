## 3. 進行

1 人 = 準備 → **3 分**（時間で自動終了）→ 着弾待ち 1 秒 → 記録 → 保存。

| 操作 | いつ | 何が起きるか |
|---|---|---|
| **Space** | 準備 / 記録 / 保存後 | 開始 / 記録して保存 / 次の参加者へ |
| **E** | 3 分の途中 | **終了希望**（安全のために実施者が止めるときも同じ）。そこで試技を終え、完走していない記録になる |
| **G** | 3 分の途中 | 持ち替え +1 |
| **D** | 3 分の途中 | 腕の下がり +1（初回の秒も残る） |
| **Tab** | いつでも | 実施者パネル（1 分ごとの投数・命中率・周期・集計）の表示切替 |
| **L** | いつでも | CSV を読み直して集計しなおす（Excel で聞き取り列を埋めたあと） |

- 参加者の画面には**残り時間だけ**を出す。投数・命中率は見せない（数字を追うと振り方が変わる）。
- 3 分のあいだだけ `ThrowInputController` を有効にする。着弾待ち・記録中は振っても何も出ない。
- 3:00 で入力を締め切り、飛翔中の弾（最長 0.65 秒）の着弾を 1 秒待ってから記録へ移る。**3:00 直前に投げた弾も数える**。
- 記録画面では 1 文字キー（E / G / D）は効かない（所見の入力と混ざらないように）。Space で保存するのは入力欄にフォーカスが無いときだけ。
- 参加者番号は保存のたびに進む。同じ日の CSV があれば起動時に読み込み、続きの番号から始まる。

### 3.1 実施者の台本（そのまま読む）

1. 大幣の持ち方とストラップを確認する（T6-USB の安全チェックと同じ）。
2. 「**あの的をねらって、3 分間ふり続けてください。疲れたり、やめたくなったりしたら、いつでも言ってください**」
   — 速さ・回数は指示しない。「がんばって」「あと少し」も言わない（励ましで疲労が隠れる）。
3. Space で開始。後ろから観察し、持ち替えは **G**、腕の下がりは **D**。
4. 「やめたい」と言われたら、引き止めずに **E**。痛み・恐怖・ストラップ逸脱が見えたら実施者の判断で **E**。
5. 終わった直後（大幣を置いてすぐ）に聞く:
   - 「腕や肩はどれくらい疲れた？ **1 まったく疲れていない 〜 5 とても疲れた**」
   - 「どこか痛いところはある？」「こわいと感じたところはあった？」
6. 「**もう一回やる？ それとも別の遊びにする？**」— 口で答えた希望ではなく、**実際に選んだほう**を記録する
   （もう一回を選んだら、その場で本当にもう 1 回できるように準備しておく。2 回目は記録しない）。
7. 表情・第一声・持ち方などを所見に書いて保存。

### 3.2 観察の基準

| 項目 | 数えるとき |
|---|---|
| 持ち替え | 大幣を持つ手を変えた・両手に持ち直した・握り直すために振りを止めた |
| 腕の下がり | 振り上げの高さが開始直後より明らかに低くなった（肘が肩より下のまま振る、など）。同じ状態が続く間は 1 回 |
| 終了希望 | 言葉・態度で「やめたい」を示した。止めたらその秒が「実施秒」に残る |

## 4. 記録

保存先は `PlaytestLogs/`（Editor はプロジェクト直下、ビルドは `persistentDataPath`）。実際のパスは実施者パネルに出る。
ファイル名は `T0-3M-1_<日付>.csv`、**1 人 1 行**（10 人で 10 行）。UTF-8 BOM 付き。

CSV の列（37 列）:

```
テストID,日付,参加者番号,責任者,クールダウン秒,フィードバック案,予定秒,実施秒,完走,終了希望,
0-60s投数,60-120s投数,120-180s投数,0-60s着弾,60-120s着弾,120-180s着弾,0-60s命中,60-120s命中,120-180s命中,
0-60s命中率,60-120s命中率,120-180s命中率,投数低下率,CD却下,周期件数,周期中央,周期p75,
持ち替え,腕の下がり,腕の下がり初回秒,疲労,痛み,恐怖,ストラップ逸脱,再挑戦,所見,周期列
```

| 定義 | 内容 |
|---|---|
| 投数 | 有効スイング確定（発射）の数。クールダウンで却下された振りは「CD却下」に別に数える（参考値） |
| 命中率 | 的に当たった着弾 ÷ 着弾（#63 と同じ）。**着弾は発射した分に入れる**（0:59.8 に投げて 1:00.3 に着いた弾は 1 分目） |
| 投数低下率 | 1 − 120-180s 投数 ÷ 0-60s 投数。完走していない・最終分に届いていない・初分が 0 なら空欄 |
| 実操作周期 | 発射と発射の間隔（秒）。#63 の `throw_interval_sec` と同じ定義。「周期列」に全間隔を空白区切りで残す |

- **空欄は欠測で、0 ではない**。途中終了で届かなかった分の投数・命中率、未回答の疲労・再挑戦は空欄で書く。
- 命中率・投数低下率・周期の中央値と p75 は見やすさのための派生列。読み戻すときは元の列（投数・着弾・命中・周期列）から計算し直す。
- 聞き取りを後から Excel で埋めるときは、**その日の追記が終わってから**開く（開いたままだと書き込めない）。埋めたら Unity で **L**。

## 5. 完了条件と判定

実施者パネルに ○×で出る（`EnduranceTestSummary`）。分母は予定人数（既定 10 人）。

| 完了条件 | 判定のしかた |
|---|---|
| 9/10 が 3 分完走 | 3:00 まで続けた人数（E で止めた人は数えない） |
| 最終 1 分の投数低下が初分比 20% 以内 | 完走者それぞれの投数低下率の**中央値**が 0.20 以下（20% ちょうどは合格） |
| 疲労中央値 2/5 以下 | 疲労 5 段階の中央値。10 人で 2 と 3 が 5 人ずつなら 2.5 で不合格 |
| 7/10 がもう一度を選択 | 実際に「もう一度」を選んだ人数 |
| 痛み・恐怖・ストラップ逸脱 0 件 | 1 件でも出たら不合格。**聞き取りが未記入の行でも数える** |
| 別日・別対象者で 2 回連続合格（19章） | 1 回分では判定できない。§7 に 2 回並べる |

- 疲労と再挑戦が入っていない行は、安全事象以外の集計に入らない（「未記入 n 行」と出る）。

### 5.1 実操作周期と 8章の負荷算術

全員分の発射間隔を束ねて中央値と p75 を出す（`CycleMedian` / `CycleP75`）。**合否の条件ではなく、8章を更新するための記録**。

8章の表は次の式で出ている（`WaveLoadArithmetic`。EditMode テストで表の値と一致を確認）:

| 大負荷ウェーブ | 総同時上限 | 必要救済/秒 = 上限 ÷ 20.94 秒 | 必要命中/秒 = × 1.094 発 | 許容される 1 投周期 = 1 ÷ 必要命中/秒 |
|---|---|---|---|---|
| +3 | 13 人 | 0.62 | 0.68 | **1.47 秒** |
| +4 | 14 人 | 0.67 | 0.73 | **1.37 秒** |
| +5 | 15 人 | 0.72 | 0.78 | **1.28 秒** |

判定（仕様書 17章 T0-3M の不合格時の処置）:

1. 中央値と p75 がともに 1.0〜1.4 秒なら **想定内**。人数案はそのまま（パネルに「p75 より短い（参考）」と出ることはある）。
2. どちらかが外れたら **想定外**。8章の表の前提（1.0〜1.4 秒）を中央値と p75 に置き換え、
   **許容 1 投周期が p75 より短い人数案を T3 候補から外す**（パネルに × と「T3 候補から外す」）。
   例: p75 = 1.45 秒 → +3（1.47）は残り、+4（1.37）・+5（1.28）は外す。

20.94 秒と 1.094 発は付録B の出現比率（負荷ウェーブ中 通常 75% / 移動 6.25% / 遠方 9.375% / 欲張り 9.375%）から仕様書が出した値。
比率が変わったら `WaveLoadArithmetic` の定数も合わせる。

## 8. 前提・未決事項

1. **仕様書 v8 17章と Issue #53 から次のように解釈した**（企画と照合してほしい）:
   - 「最終 1 分の投数低下が初分比 20% 以内」は、**完走者それぞれの低下率の中央値**で見た。
     「疲労中央値」と揃え、1 人の極端な値で全体が落ちないようにするため。全員が 20% 以内を求める解釈なら判定を変える。
   - 「実操作周期」は**発射と発射の間隔すべて**（3 秒以上の停止をはさんだ間隔も含む）。#63 の `throw_interval_sec` と同じ定義にして、
     T3 のログと比べられるようにした。中央値・p75 なので、数回の長い停止には引きずられにくい。
   - 「想定 1.0〜1.4 秒から外れた場合」は、**中央値か p75 のどちらかが範囲外**のとき、とした。
     仕様書の文面どおり、p75 より短い周期を要求する人数案を外すのは**想定外だったときだけ**。
     p75 が想定内（例: 1.35 秒）でも +5（1.28 秒）は p75 より短いので、そのときは参考表示にとどめている。常に外す運用にするなら `EnduranceTestSummary` の 1 行を変える。
   - 「実際の再挑戦選択」は、口頭の希望ではなく**その場で本当にもう 1 回を選んだか**。
   - 疲労 5 段階の文言は「1 まったく疲れていない 〜 5 とても疲れた」とした。19章の楽しさ・手応えなどと同じ 5 段階。
2. **ゲート順**: 仕様書のゲート順は T0-A/B → T0-CD → T0-3M。この Issue では計測の道具（シーン・ビルド・記録・集計）までを用意した。
   **対象者での実施は T0-A/B と T0-CD の採用値が出てから**行う（§1 の値を差し替えてから）。
3. **ESP32 の振動はファームウェア未対応**（#64 と同じ前提）。T0-A/B で振動込みの案を採用していた場合は、同じ条件で通す。
4. 着弾は Unity のフレーム時間で進むので、3:00 締切後の待ち（1 秒・実時間）より前にフレームが大きく止まると、最後の数発の着弾を取りこぼしうる。
   本番の 60fps では最長 0.65 秒で着くので問題にならないが、実機での B2 で 3:00 直前の投擲が数えられていることを確かめる。
5. 動画撮影は必須にしていない（合否の正本が動画だった T0-CD と違い、ここでは実施者の観察と聞き取りが正本）。
   腕の下がりを後から見返したい場合は、同意を取ったうえで撮影する（19章）。
