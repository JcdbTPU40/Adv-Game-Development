## 3. 学習中は競技得点に入れない（正本：18章「学習中は競技用の得点・評価・ランクを加算しない」、8章「0:30.000で全競技カウンタを0へ初期化」）

- 0:00 に `ScoreManager.SetPractice(true)` / `ShrineRating.SetPractice(true)`。練習中は縁・福の連なり C・救済数・伝播得点・5秒タイマー・評価値・現在／最高ランクが動かない。誤投擲でも連なりが切れる合図（`onMiss`）を出さない（「罰を与えない」）。

- **0:30.000**：`GameSession`（実行順 -300）が `CompetitionStarted` を出し、段階学習が
  1. 練習中をやめる
  2. `ScoreManager.ResetAll()`（縁=0、C=0、救済数=0。`onReset` でご加護もやめる）
  3. `ShrineRating.ResetAll()`（評価=0、現在／最高ランク=C、ランクC停滞タイマー=0）
  4. `t1_counter_reset` を記録

  6. 補充を再開（時間割の上限まで通常客から）

- 大祓（未実装）・ご加護（C が増えないので発動しない）・天候のゲーム効果は学習中に出ない。

## 4. 学習区間の危険円はスクリプト固定値（正本：v7 変更点12、18章「0:18〜0:30の二重円は時間経過ではなくスクリプトで与えたD=65」）

- 学習の客は置いた瞬間に `CustomerState.LockDanger` で D を固定する（二重円の客は 65、ほかは 0）。固定中は時間・笑顔の伝播・デバッグ用の設定で D が動かず、100 未満に収めるので黒客にならない（「この30秒は黒客化しない」）。
- D=65 は危険円の表示しきい値 50（付録B UI.DANGER）以上なので足元に薄い赤の円が出る。二重円は #55 の `PriorityRescue`（D が最大の1人）がそのまま付けるので、表示・+50 の判定・ログの優先対象ID が同じ客を指す。
- 0:30 以降は通常のルール（D は時間で進み、二重円は D 最大の1人）。

## 10. 決めたこと・レビューで見てほしいこと

1. **0:30 をまたいだ弾**：0:29.72 に投げて 0:30.38 に着弾した救済は競技の縁に入った（PlayMode で実際に起きた）。企画書は 3:00 側（受理時刻で判定）しか決めていない。0:30 も受理時刻で「学習の弾」として捨てるなら、弾に受理時刻を持たせて判定する（1行程度の変更）。企画に確認したい
2. **学習の客は 0:30 で D=0 から通常ルール**にした。D=65 のまま競技に入ると、見抜くが未達の人だけ開始直後に黒客が出やすくなり、「参加者ごとに開始条件が変わる」（v8 変更点11）ことになるため
3. **二重円の客の色は縁結び（桃）・中の帯**。青（学業成就）と紫（厄除け安全）は色相が近く（#59）、緑と金は P型／D型で近いので避けた。`priorityColor` で変えられる
4. **ボタンの脈動は画面の代わり**。ボタン箱の LED を Unity から光らせる経路はまだない（プログラムA：ESP32 側）。`ButtonPulseChanged` をつなげば、画面の列と同じ値で LED を脈動できる
5. **照準反応はカプセルの客を振り向かせて少し大きくする**だけ。顔の向き・表情のアニメができたら差し替える
6. **自由練習中の二重円**：学習の客はみな D=0 固定なので、二重円は #55 の同値順（遠い → active が早い → ID）で1人に付く。自由練習では二重円に意味を持たせていない

8. **教える3で置く客**：前の段階で救えなかった客はそのまま使い、足りない色だけ置く。救った直後の色は 1.5秒あけて置き直す（同じ場所に同じ色がすぐ出ると、救えたことが見えにくいため）
