## 1. 比べるもの（テスト前に固定する）

変えるのは**振りピークからの 3 つの時刻差だけ**。音の素材・弾の見た目・飛翔時間・判定・的の位置は A/B で同じ。

| | 投擲SE | 軌跡出現 | 振動開始 |
|---|---|---|---|
| **案A「同時」** | 0 ms | 0 ms | 0 ms |
| **案B「音→振動→軌跡」** | 0 ms | 45 ms | 20 ms |

- これは**初期値**。テストの前に企画・サウンドで決めた値を `AbTest` の Inspector（`variantA` / `variantB`）に入れて固定し、
  下の実施記録へ書き写す。Play 時に Console へ `案A … / 案B …（違い N 項目）` と出るので、それを貼るのが早い。
- 案A を「本番の今の実装そのまま（3 つとも同時）」にしてあるのは、**基準**を 1 つ持っておくため。
- 時刻差は飛翔時間（最短 0.25 秒）より十分短くする。100 ms を超える値は弾が飛び始めてから出ることになる。
- **不合格だったとき**は、投擲SE・軌跡出現・振動開始を **1 つずつ**直して新しい A/B を組む
  （`FeedbackVariant.CountDifferences` が違いの数を返す。2 回目以降は 1 であることを確かめる）。

### 1.1 時刻差はどう作っているか

- **0 ms の出口**は `ThrowInputController` から呼ばれたその場（＝本番とまったく同じ呼び出し）で出す。
- **0 より大きい出口**は `FeedbackTimingShifter.Update` で出すのでフレーム単位に丸まる。
  `uncapFrameRate`（既定 ON）でフレーム上限を外してあり、実測の丸めは数 ms（下の確認記録参照）。
  実測値は実施者パネル（Tab）に「実測 SE / 軌跡 / 振動 … ms（丸め最大 N ms）」として出る。
- 軌跡だけは弾側（`OmamoriProjectile`）が飛翔時間で測るので、指定した時刻差がそのまま出る。

## 3. 進行

1 人 = 45 秒 → 60 秒休憩 → 45 秒 → 聞き取り（合計 2 分半＋聞き取り）。

| 操作 | 何が起きるか |
|---|---|
| **Space** | 準備 → 開始 / 記録後 → 次の参加者へ |
| **Tab** | 実施者パネル（投数・実測時刻差・集計）の表示切替 |
| **Backspace** | 今のフェーズを飛ばす（言い直し・休憩の切り上げ用） |

- 参加者の画面には**「案1 / 案2」と残り秒数**しか出さない。どちらが案A かは伏せる（実施者パネルは参加者から見えない位置で見る）。
- 参加者番号が**奇数なら A→B、偶数なら B→A**。10 人で 5 人ずつになる（`AbTestPlan.OrderOf`）。
  番号は保存のたびに自動で 1 増える。
- 休憩と聞き取りの間は入力を止めるので、振っても音も弾も出ない。
- **自発投数は参加者に見せない**（回数を意識させると「自発」でなくなる）。実施者パネルにだけ出る。

### 3.1 実施者の台本（そのまま読む）

1. 「大幣を持って、好きなだけ振ってください。的に当てても当てなくてもかまいません」
   — 得点も参拝客も無いことを先に伝える。当てる課題だと思わせない。
2. 45 秒たったら「いったん置いて休んでください」（60 秒）。
3. 2 回目の前に「さっきと少し違う感じにしてあります。同じように好きなだけ振ってください」。
4. 聞き取り（画面の順どおり）:
   - 「案1 の手応えは 5 段階でいくつですか」→ 案2 も同じく
   - 「案1 のあと、すぐもう一度振りたいと思いましたか（はい / いいえ）」→ 案2 も同じく
   - 「**どちらか必ず選ぶとしたら**どちらを採用しますか」→ 理由をそのままの言葉で書き取る
   - ずれ（音・映像・振動が合っていない感じ）の指摘があればチェック
   - 痛み・恐怖・ストラップ逸脱があればチェック（**1 件でもあればその場で中止**して原因を直す）
5. 「記録して次へ」で保存。Space で次の参加者へ。

## 4. 記録

- 保存先: `PlaytestLogs/<テストID>_<日付>.csv`（Editor ではプロジェクト直下、ビルドでは `persistentDataPath`）。
  1 人ずつ追記するので途中で落ちてもそこまで残る。UTF-8 BOM 付きなので Excel でそのまま開ける。
- 同じテストID・同じ日付のファイルがあれば起動時に読み込み、参加者番号と集計の続きから始まる。
- 列（20 列）:

```
テストID,日付,参加者番号,責任者,提示順,
案A自発投数,案B自発投数,案A却下数,案B却下数,
案A手応え,案B手応え,案Aもう一度,案Bもう一度,
採用案,同期ずれ指摘,痛み,恐怖,ストラップ逸脱,理由,表情・声
```

- 自由記述の改行は空白へ置き換えて 1 行に収める。カンマ・引用符が入っても列はずれない。
- 「却下数」はクールダウン中に振ってしまった回数。「すぐもう一度振りたい」の**行動側の手がかり**として見る
  （合否には使わない。クールダウン値そのものは T0-CD #50 の担当）。
- 表情・声は実施者がその場で短く書く。日本語入力が間に合わなければ空のまま保存し、あとから CSV に足してよい。

## 5. 完了条件と判定

実施者パネルに ○×で出る（`AbTestSummary`）。分母は**予定人数**（既定 10 人）。

| 完了条件 | 判定のしかた |
|---|---|
| 8/10 が採用案を手応え 4/5 以上 | 各自が選んだ採用案への回答で数える |
| 8/10 が「すぐもう一度振りたい」 | 同じく**採用案への回答**で数える |
| 7/10 以上が同じ案を選ぶ | 採用案の多いほうの人数 |
| 映像・音・振動の同期ずれ指摘が 2/10 以下 | 指摘した人数 |
| 痛み・恐怖・ストラップ逸脱 0 件 | 1 件でも出たら不合格 |
| （記録人数） | 10 人そろうまでは合格にしない |

- 人数を変えた場合も同じ割合（8割・7割・2割）で判定する。
- 記入が足りない記録は集計に入れず「未記入 N 人」として出る。
- **合格 → 仕様固定は、別日・別対象者で 2 回連続合格してから**。1 回分では判定できないので下の実施記録に 2 回並べる。
- **不合格 → 参拝客制作を停止**し、3 つの時刻差を 1 つずつ直して新しい A/B を組む（§1 参照）。

## 8. 前提・未決事項

- 仕様書 v8 本文はリポジトリに無いため、Issue #49 の記述から次のように解釈した。仕様書と照合してほしい：
  1. **「すぐもう一度振りたい」の 8/10 は採用案への回答**で数える（案ごとに聞くが、合否は採用案側を見る）
  2. **自発投数**＝45 秒間の有効スイング数（クールダウンで却下された振りは別列の参考値）
  3. **「同じ的・重量・判定」**のうち的と判定はシーンに焼き、重量は実機の運用（同じ大幣・同じストラップ）で担保する
  4. **案A は本番の現状（3 つとも同時）**を基準として置いた。企画で別の 2 案に決まったら Inspector で入れ替える
  5. 標準ターゲットに当たったときの短い光りは A/B 共通。比べる対象ではない
- 時刻差はフレーム単位に丸まる（#64 の投擲SE 予算 80ms に対して数 ms）。**無線の遅延・オーディオ出力の遅延**は
  この値に含まれない。体感としてのずれはこのテストの「同期ずれ指摘」で拾う。
- ESP32 の振動はファームウェア未対応（#64）。**振動はゲームパッドでしか出ない**ので、
  振動を含めて比べるならゲームパッドを握らせるか、ファームウェア対応を待つ。対応前に実施する場合は
  案A・案B の振動時刻差を 0 にそろえ、「投擲SE と軌跡出現の時刻差」だけの A/B とする（この場合も 1 テスト 1 仮説）。
- SE はすべて #64 の仮素材（合成音）。正式素材が届いたら `GameFeedbackDirector` の枠に入れるだけで差し替わるが、
  **素材が変わったら A/B はやり直し**（音そのものが変数になるため）。
