### ⚠ 識別テスト時は `H`（ゲージ凍結）を ON にすること

ゲージ凍結が OFF だと、自然上昇で常に誰かが怒って退場するため、
**目標15体でも実際に定位置に立っているのは13体前後にしかならない**（モック上の実測値）。
体数ごとの識別可否を測るときは必ず `H` で凍結してから提示すること。
画面の状態表示に出る「定位置」の数が、実際に並んでいる体数。

逆に、5章の補充テンポを見るときは凍結を OFF にする（退場と補充が起きないと測れないため）。

## 6. 発見した問題点

> 次の Issue にそのまま落とせる粒度で書くこと。
> 「何が」「どの条件で」「どう困るか」が1行で分かる状態を目安にする。

### モック構築時点で判明しているもの（実測前）

- [ ] **補充ディレイのぶん、画面上の体数が常に目標を下回る。**
      スポーン遅延2.0s＋歩行3.5s の間は欠員になるため、目標15体でも定位置は13体前後。
      → 本番で「祭事は15人」と定義するなら、それが目標値なのか実効値なのかを決める必要がある。
- [ ] **頭上ゲージが遠バンドで密集して重なる。**
      距離スケール ON でも下限クランプ(0.45)が効き、遠くの客ではバーが客の見かけ幅より広くなる。
      → `MockGaugeHud` の `barWidth` / `scaleClamp` の適正値を実測で決める必要がある。
- [ ] **輪郭の太さモードによって遠バンドの見え方が大きく変わる。**
      ワールド固定だと遠くで潰れ、画面上一定だと近くで太くなりすぎる傾向。
      → #45 の本番アウトラインでも同じ問題が出るはずなので、太さの決め方を仕様として決めておく必要がある。

### 輪郭表現について（案A / 案B の比較結果）

`MockCustomerOutline.cs` の冒頭コメントに記載。要点:

- **案A インバートハル（採用）** — 同じメッシュを法線方向に押し出し、裏面だけ描いて縁取りにする。
  輪郭の太さを独立変数として振れ、#45 の本番ステンシルアウトラインと見え方が近いため、
  検証結果をそのまま本番に転用できる。
- **案B Emission / リム発光（比較用に同居）** — 面全体が光るため「輪郭」の検証にならず、
  密集時に隣の客と発光が溶け合う。Bloom 設定に結果が左右され変数も増える。

実行中に `O` キーで切り替えて直接比較できる。本番へ差し替えるときは
`MockCustomerOutline` の中身だけを置き換えればよい（外から見た API は変えていない）。

### `CustomerGaugeHud`（既存）を使わなかった理由

`MockGaugeHud.cs` の冒頭コメントに記載。要点は 12〜15 体で次の3点が検証の邪魔になるため。

1. `OnGUI` 内で毎回 `FindObjectsByType` している（`OnGUI` は 1 フレームに複数回呼ばれる）
2. バー幅が固定ピクセルで遠近感が消え、密集すると重なって読めない
3. 描画順が探索順まかせで、手前の客のバーが奥の客に隠れることがある

加えて既存版には黒客（黒ゲージ）の概念が無く、#44 の検証項目を満たせない。
既存ファイルには手を入れず、Mock 用の派生版を新規追加した。
